1. INTRODUCTION
Direct-current (DC) motors are widely used in industrial automation to drive conveyors, pumps,
fans, robotic joints and machine tools, because their speed can be varied smoothly over a wide
range. The speed of a DC motor is nearly proportional to the average voltage applied to its
armature, so speed control means controlling that voltage. Reducing the voltage with a series
resistor or a linear regulator wastes power as heat and weakens the torque at low speed, whereas a
switching method gives precise control with very little loss.
Pulse Width Modulation (PWM) is such a switching method. The supply is switched fully on and
fully off at a fixed, high frequency, and the fraction of each period for which it is on, called the duty
cycle, sets the average voltage: Vavg = D × Vs, where D = Ton / T. A duty cycle of 25 % on a 12 V
supply gives an average of 3 V, and 100 % gives the full 12 V. The inductance and inertia of the
motor smooth the pulses, so it runs at a steady speed decided by D. Because PWM is a digital
signal, it is generated directly by the microcontroller without a DAC and is exactly repeatable,
which is the precise control that an automation system requires.
In this ALM activity the speed control is implemented using the PWM module of the LPC2148, a
32-bit microcontroller from NXP based on the ARM7TDMI-S core. Its main features are listed in
Table 1. The PWM module is built around a 32-bit timer with a prescaler and seven match registers,
so the period and the on-time of the output are fixed by hardware and the CPU is free while the
pulses are being produced.

The proposed system uses three on-chip modules of the LPC2148 working together. The PWM
module generates a 10 kHz PWM signal on the PWM2 pin (P0.7), which is applied to the enable
input of an L293D motor driver, so the duty cycle decides the motor speed. Timer0 raises an
interrupt every two seconds so that the duty cycle is stepped through a speed table (20 %, 40 %, 60
%, 80 %, 100 % and back). UART0 sends the duty cycle, the average voltage and the speed to a PC.
The complete program is written in Embedded C and built with Keil µVision; the generated HEX
file is loaded into a Proteus simulation of the LPC2148 with a virtual terminal.

2. WORKFLOW DESCRIPTION
The speed controller works as a continuous select–update–drive cycle that is paced by Timer0. The
complete workflow is shown in Figure 1; each numbered stage is explained below.




         Figure 1: Overall Workflow of the DC Motor Speed Control Using LPC2148 PWM
 1. Speed command. The required speed is held in the program as a table of duty cycles (20, 40, 60,
    80 and 100 %). In a real plant the command could come from a potentiometer or a PLC.
 2. LPC2148 CPU. The CPU takes the next value from the table and decides the new duty cycle. It
    writes the value to the match register PWMMR2 and latches it with PWMLER.
 3. PWM module. The PWM timer counts microseconds from the prescaled PCLK. PWMMR0 fixes
    the period (100 µs) and PWMMR2 fixes the on-time, so the module generates the pulses without
    CPU help.
 4. PWM2 output. In single-edge mode the output is set at the start of every period and cleared when
    the counter matches PWMMR2. The signal appears on pin P0.7 at 10 kHz.
 5. Motor driver. The 3.3 V PWM signal drives the enable pin of an L293D H-bridge. P0.4 and P0.5
    set the direction, and the driver switches the 12 V motor supply at the PWM rate.
 6. DC motor. The motor sees an average voltage of duty × 12 V and runs at a speed proportional to
    it. A higher duty cycle gives a higher speed.
 7. Timer0 pacing. Timer0 is programmed to match every two seconds and raises an interrupt. The
    interrupt routine only sets a flag; the main program then moves to the next speed step.
 8. UART0 monitor. The step number, duty cycle, average voltage and speed are sent as text at 9600
    baud to a PC (or the virtual terminal), and the cycle repeats.

4.2 PWM Configuration Steps
The PWM module is configured with the following steps; the values used are collected in Table 6.
 1. Select the pin function. PINSEL0 bits 15:14 are set to 10 so that P0.7 becomes the PWM2
     output.
 2. Set the clock. The PLL gives CCLK = 60 MHz and VPBDIV = 0 gives PCLK = CCLK / 4 = 15
     MHz.
 3. Reset the PWM timer. PWMTCR = 0x02 holds the counter in reset while it is configured.
 4. Set the prescaler. PWMPR = 14 makes the counter tick every (14 + 1) / 15 MHz = 1 µs.
 5. Set the period. PWMMR0 = 100 gives a period of 100 µs, that is a PWM frequency of 10 kHz.
 6. Set the duty cycle. PWMMR2 = duty value (0 to 100) fixes the on-time, so duty (%) =
     PWMMR2 / PWMMR0 × 100.
 7. Choose the match action. PWMMCR = 0x02 resets the counter when it matches PWMMR0.
 8. Latch the values. PWMLER = 0x05 loads the new PWMMR0 and PWMMR2 at the next period.
 9. Enable the output. PWMPCR bit 10 (PWMENA2) = 1 enables PWM2 in single-edge mode.
 10. Start the PWM. PWMTCR = 0x09 enables the counter (bit 0) and the PWM mode (bit 3).
                                 Table 6: PWM configuration parameters
         Parameter                Register / bits                                  Value used
 Pin function                PINSEL0 bits 15:14             10 (P0.7 = PWM2)
 PWM timer clock             PWMPR                          14 → 1 µs per tick (PCLK = 15 MHz)
 Period (frequency)          PWMMR0                         100 → 100 µs (10 kHz)
 Duty cycle                  PWMMR2                         20, 40, 60, 80, 100 (% of period)
 Match control               PWMMCR                         0x02 (reset counter on MR0)
 Latch enable                PWMLER                         0x05 at start, 0x04 for later duty updates
 Output enable / mode        PWMPCR bit 10                  1 (PWMENA2, single-edge)
 Timer control               PWMTCR                         0x02 reset, then 0x09 (counter + PWM enable)

4.4 PWM Initialization and Duty Update
pwm_init() performs the configuration steps of Section 4.2. pwm_set_duty() writes a new value to
PWMMR2 and latches it with PWMLER; the new duty cycle takes effect at the start of the next period,
so the output never produces a shortened or glitched pulse. For 100 % the match value is set above the
period so that it never matches and the output stays high.
  void pwm_init(void)
  {
      PINSEL0 = (PINSEL0 & ~(3u << 14)) | (2u << 14);    /* P0.7 = PWM2           */
      PWMTCR = 0x02;                            /* reset the counter             */
      PWMPR   = (PCLK_HZ / 1000000UL) - 1;     /* 14 -> 1 us per tick            */
      PWMMR0 = PWM_PERIOD;                      /* 100 us period -> 10 kHz       */
      PWMMR2 = speed_table[0];                  /* initial duty 20 %             */
      PWMMCR = 0x02;                            /* reset counter on MR0 match    */
      PWMLER = 0x05;                            /* latch MR0 and MR2             */
      PWMPCR = (1u << 10);                      /* PWMENA2, single-edge          */
      PWMTCR = 0x09;                            /* counter enable + PWM enable   */
  }
  void pwm_set_duty(unsigned int duty)
  {
      if (duty >= 100) PWMMR2 = PWM_PERIOD + 1;    /* never matches: always high */
      else             PWMMR2 = duty;              /* on-time = duty x 1 us      */
      PWMLER = 0x04;                            /* latch MR2 at next period      */
  }


4.5 UART0 Initialization and Transmission
UART0 is configured for 9600 baud, 8 data bits, no parity and 1 stop bit. PINSEL0 bits 3:0 are set to
0101 so that P0.0 is TXD0 and P0.1 is RXD0. With DLAB = 1, the divisor PCLK / (16 × 9600) = 97.7,
rounded to 98, is written to U0DLL (actual baud rate 9566, error 0.35 %). uart0_putc() waits until
THRE = 1 in U0LSR and writes the character to U0THR; uart0_puts() sends a complete string.
4.6 Timer0 Initialization and Interrupt
T0PR = 14999 makes Timer0 tick every 1 ms and T0MR0 = 1999 produces a match after 2000 ticks,
which is 2 s. T0MCR = 0x03 generates an interrupt and resets the counter at every match. Timer0 is
source 4 of the VIC and uses vectored slot 0. The interrupt routine only sets step_flag, clears the MR0
flag by writing 1 to T0IR and writes 0 to VICVectAddr; the keyword __irq makes the ARM compiler
generate the interrupt entry and exit code.

4.7 Data Processing and Report
report() converts the duty cycle into the average motor voltage (tenths of a volt = duty × 12 / 10) and
into an approximate no-load speed (duty × 30 RPM, assuming a 3000 RPM motor at full voltage), using
integer arithmetic only. The values are formatted with sprintf() and sent through UART0.
4.8 Complete Program
The complete program initialises the PLL, GPIO, PWM, UART0 and Timer0 in that order, sends the
start-up banner and then enters an endless loop. The loop checks the volatile flag step_flag, which
Timer0 sets every two seconds; when it is set, the flag is cleared, the next duty cycle is written to the
PWM module and the result is reported through UART0.
  /* DC Motor Speed Control using PWM - LPC2148 - main.c (Keil uVision, Embedded C) */
  #include <LPC214x.h>
  #include <stdio.h>
  #define PCLK_HZ      15000000UL       /* PCLK = CCLK / 4 = 15 MHz              */
  #define BAUD         9600UL
  #define STEP_MS      2000UL           /* speed changes every 2 s               */
  #define PWM_PERIOD 100                /* PWMMR0: 100 ticks x 1 us = 100 us     */
  #define MOTOR_IN1    (1u << 4)        /* P0.4: L293D IN1                       */
  #define MOTOR_IN2    (1u << 5)        /* P0.5: L293D IN2                       */
  #define NUM_STEPS    9
  const unsigned char speed_table[NUM_STEPS] = {20, 40, 60, 80, 100, 80, 60, 40, 20};
  volatile unsigned char step_flag = 0;       /* set by the Timer0 interrupt     */
  unsigned int step_no = 0;
  /* ---------------------------- clock ----------------------------------- */
  void pll_init(void)
  {
      unsigned int t = 100000;                   /* lock time-out counter         */
      PLL0CFG = 0x24;                            /* M = 5, P = 2 -> CCLK = 60 MHz */
      PLL0CON = 0x01;                            /* enable PLL                    */
      PLL0FEED = 0xAA; PLL0FEED = 0x55;
      while (!(PLL0STAT & (1u << 10)) && --t); /* wait for PLL lock (time-out) */
      PLL0CON = 0x03;                            /* enable and connect PLL        */
      PLL0FEED = 0xAA; PLL0FEED = 0x55;
      MAMTIM = 0x03;                             /* flash accelerator timing      */
      MAMCR = 0x02;                              /* fully enabled                 */
      VPBDIV = 0x00;                             /* PCLK = CCLK / 4 = 15 MHz      */
  }
  /* ---------------------------- GPIO ------------------------------------ */
  void gpio_init(void)
  {
      IO0DIR |= (MOTOR_IN1 | MOTOR_IN2);         /* P0.4, P0.5 as outputs         */
      IO0SET = MOTOR_IN1;                        /* IN1 = 1                       */
      IO0CLR = MOTOR_IN2;                        /* IN2 = 0 -> forward            */
  }
  /* ---------------------------- PWM ------------------------------------- */
  void pwm_init(void)
  {
      PINSEL0 = (PINSEL0 & ~(3u << 14)) | (2u << 14);      /* P0.7 = PWM2           */
      PWMTCR = 0x02;                             /* reset the counter             */
      PWMPR    = (PCLK_HZ / 1000000UL) - 1;      /* 14 -> 1 us per tick           */
      PWMMR0 = PWM_PERIOD;                       /* 100 us period -> 10 kHz       */
      PWMMR2 = speed_table[0];                   /* initial duty 20 %             */
      PWMMCR = 0x02;                             /* reset counter on MR0 match    */
      PWMLER = 0x05;                             /* latch MR0 and MR2             */
      PWMPCR = (1u << 10);                       /* PWMENA2, single-edge          */
      PWMTCR = 0x09;                             /* counter enable + PWM enable   */
  }
  void pwm_set_duty(unsigned int duty)
  {
      if (duty >= 100) PWMMR2 = PWM_PERIOD + 1;     /* never matches: always high */
      else               PWMMR2 = duty;             /* on-time = duty x 1 us      */
      PWMLER = 0x04;                             /* latch MR2 at next period      */
  }
  /* ---------------------------- UART0 ----------------------------------- */
  void uart0_init(void)
  {
      PINSEL0 = (PINSEL0 & ~0x0Fu) | 0x05u;      /* P0.0 = TXD0, P0.1 = RXD0      */
      U0LCR = 0x83;                              /* 8N1, DLAB = 1                 */
      U0DLL = ((PCLK_HZ / 16) + (BAUD / 2)) / BAUD;     /* divisor = 98           */
      U0DLM = 0;

    U0FCR = 0x07;                           /* enable and reset FIFOs        */

void uart0_putc(char c)
{
    while (!(U0LSR & 0x20));                  /* wait until THR is empty       */
    U0THR = c;
}
void uart0_puts(const char *s)
{
    while (*s)
        uart0_putc(*s++);
}
/* ---------------------------- Timer0 ---------------------------------- */
__irq void timer0_isr(void)
{
    step_flag = 1;                            /* 2 s has elapsed               */
    T0IR = 0x01;                              /* clear MR0 interrupt flag      */
    VICVectAddr = 0;                          /* end of interrupt              */
}
void timer0_init(void)
{
    T0TCR = 0x02;                             /* reset counter                 */
    T0PR = (PCLK_HZ / 1000) - 1;              /* 14999 -> 1 ms per tick        */
    T0MR0 = STEP_MS - 1;                      /* 1999 -> match every 2 s       */
    T0MCR = 0x03;                             /* interrupt + reset on MR0      */
    VICVectAddr0 = (unsigned long)timer0_isr;
    VICVectCntl0 = 0x20 | 4;                  /* slot 0 enabled, Timer0 = 4    */
    VICIntEnable = (1u << 4);
    T0TCR = 0x01;                             /* start Timer0                  */
}
/* ------------------------- report over UART0 -------------------------- */
void report(unsigned int duty)
{
    char buf[40];
    unsigned int v10 = (duty * 6u) / 5u;      /* tenths of a volt (12 V supply) */
    sprintf(buf, "Step No       : %02u\r\n", step_no);   uart0_puts(buf);
    sprintf(buf, "PWM Duty      : %u %%\r\n", duty);     uart0_puts(buf);
    sprintf(buf, "Avg Voltage : %u.%u V\r\n", v10 / 10, v10 % 10); uart0_puts(buf);
    sprintf(buf, "Motor Speed : %u RPM\r\n", duty * 30u);            uart0_puts(buf);
    uart0_puts("Direction     : FORWARD\r\n");
    uart0_puts("--------------------------------\r\n");
    uart0_puts("PWM Updated Successfully\r\n\r\n");
}
/* ---------------------------- main ------------------------------------ */
int main(void)
{
    unsigned int idx = 0;
    pll_init();
    gpio_init();
    pwm_init();
    uart0_init();
    timer0_init();
    uart0_puts("================================\r\n");
    uart0_puts("DC MOTOR SPEED CONTROL USING PWM\r\n");
    uart0_puts("================================\r\n");
    while (1)
    {
        if (step_flag)                        /* set every 2 s by Timer0       */
        {
            step_flag = 0;
            pwm_set_duty(speed_table[idx]); /* update PWMMR2 and latch         */
            step_no++;
            report(speed_table[idx]);
            idx = (idx + 1) % NUM_STEPS;
        }
    }
}

7. CONCLUSION
A DC motor speed controller was designed and implemented around the PWM module of the
LPC2148 microcontroller. The PWM timer, with PWMPR = 14 and PWMMR0 = 100, generates a
10 kHz signal on P0.7 whose duty cycle, set through PWMMR2, fixes the average voltage across
the motor and therefore its speed. The speed was stepped from 20 % to 100 % and back, and the
status was sent to a PC through UART0 at 9600 baud, 8N1.
The PWM module is essential because it produces accurate, jitter-free pulses in hardware, so the
CPU is not occupied with switching the output and the duty cycle can be changed in a single
register write. The latch enable register makes every change take effect at a period boundary, and

                                                 17
Timer0 makes the speed steps periodic and independent of the program flow. The integration of the
three modules makes the software short, deterministic and easy to extend.
The program was developed in Embedded C using Keil µVision: the LPC2148 project was created,
main.c was added, the target was configured for a 12 MHz crystal, the project was built and the
HEX file was generated for the simulation. Such a controller can be applied to conveyor drives,
pumps and fans, robotic joints, and other speed-controlled loads. Possible future improvements are:
   •   closed-loop control using an encoder or tachogenerator and a PI controller;
   •   setting the speed from a potentiometer through the on-chip ADC;
   •   reversing the direction through P0.4 and P0.5 with a soft-start ramp;
   •   adding current sensing for overload protection; and
   •   sending the speed commands and receiving feedback through UART0 from a PC or PLC.
