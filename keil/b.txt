                                  1. INTRODUCTION
A data logger is an electronic system that automatically measures one or more physical
quantities, converts the measurements into digital form and records or transmits them at fixed
intervals without continuous human supervision. Typical uses are in greenhouses, cold-storage
rooms, weather stations, laboratories and industrial plants, wherever parameters such as
temperature, light intensity or soil moisture must be observed over a long period.
A remote data logger extends this idea by separating the place where the data is measured from
the place where it is analysed. The sensing unit is installed at the monitored location, while the
readings are sent to a computer through a communication link so that an operator can view, store
and process them without being present at the site. Continuous monitoring is necessary because
many physical parameters change slowly and unpredictably; a periodic record makes it possible
to detect abnormal conditions, study trends and take corrective action in time.
The sensors used for such parameters usually produce a continuously varying analog voltage,
whereas a microcontroller can process only digital numbers. An analog-to-digital converter
(ADC) therefore forms the bridge between the sensors and the processor. In this ALM activity
the remote data logger is implemented using the LPC2148, a 32-bit microcontroller from NXP
based on the ARM7TDMI-S core. Its main features are listed in Table 1. Because the ADC,
UART and timers are on the chip, no external converter or communication IC is needed apart
from the sensors and a serial-level interface.

The proposed system uses three on-chip modules of the LPC2148 working together. The ADC
samples the voltages from three analog sensors (an LM35 temperature sensor, an LDR light
sensor and a soil-moisture sensor) connected to separate input channels. Timer0 generates an
interrupt every second so that the readings are taken periodically and not at random. UART0
then transmits the processed readings as text to a PC, where they are displayed on a serial
terminal. The complete program is written in Embedded C and built with Keil µVision; the
generated HEX file is loaded into a Proteus simulation of the LPC2148 whose virtual terminal
displays the UART output.

                       2. WORKFLOW DESCRIPTION
 The remote data logger works as a continuous acquire–process–transmit cycle that is paced by
Timer0. The complete workflow is shown in Figure 1; each numbered stage is explained below.




             Figure 1: Overall Workflow of the Remote Data Logger Using LPC2148
 1. Analog sensors. Three sensors measure the quantities to be logged: an LM35 temperature
    sensor (10 mV per °C), a light-dependent resistor (LDR) connected as a voltage divider,
    and a soil-moisture sensor with an analog output. Each produces a voltage that varies
    continuously with the measured quantity.
 2. Sensor signal conditioning. The sensor outputs are brought into the 0 – 3.3 V range
    accepted by the LPC2148 analog pins. A series resistor and a small capacitor at each input
    (for example 1 kΩ and 0.1 µF) form a low-pass filter that suppresses noise. The analog
    inputs are not 5 V tolerant and must never exceed VREF.
 3. LPC2148 ADC. ADC0 is a 10-bit successive-approximation converter. The sensors are
    connected to channels AD0.1, AD0.2 and AD0.3 (pins P0.28, P0.29 and P0.30), and an
    analog multiplexer connects one channel at a time to the converter (Table 2).
 4. 10-bit digital conversion. Each conversion returns a number between 0 and 1023 in the
    RESULT field of AD0GDR, proportional to the input voltage: Vin = ADC × 3.3 / 1023.
 5. Data processing. The CPU converts each count into an engineering value (tenths of °C for
    the LM35, percentage for the LDR and soil moisture) using integer arithmetic and prepares
    the ASCII text lines for transmission.
 6. Timer0 periodic trigger. Timer0 is programmed to match every second and raises an
    interrupt. The interrupt routine only sets a flag; the main program then performs one
    complete acquisition cycle, so the sampling is exactly periodic and the processor is free
    between samples.
 7. UART0 transmission. The text is written one character at a time to the transmit holding
    register U0THR at 9600 baud, 8 data bits, no parity and 1 stop bit, on pin P0.0 (TXD0).
 8. PC / serial terminal. A serial-level converter (or the virtual terminal in the simulation)
    receives the data, and the terminal window displays the sample number and the three
    readings. The program then waits for the next Timer0 interrupt and the cycle repeats.

4.2 ADC Initialization
PINSEL1 is first cleared and then written so that P0.28, P0.29 and P0.30 become the analog
inputs AD0.1, AD0.2 and AD0.3. AD0CR powers up the converter (PDN = 1) and sets CLKDIV
= 3, giving an ADC clock of 15 MHz / 4 = 3.75 MHz, below the 4.5 MHz limit (Table 6).
  void adc_init(void)
  {
      PINSEL1 &= ~((3u << 24) | (3u << 26) | (3u << 28));
      PINSEL1 |= ((1u << 24) | (1u << 26) | (1u << 28)); /* AD0.1, AD0.2, AD0.3 */
      AD0CR = (1u << 21) | (3u << 8);          /* PDN = 1, CLKDIV = 3 (3.75 MHz) */
  }

4.3 ADC Reading
adc_read() selects one channel through the SEL field, starts a conversion with START = 001,
waits for the DONE flag (bit 31 of AD0GDR) and returns the 10-bit RESULT field (bits 15:6).
The START bits are then cleared so that the channel can be changed safely for the next
conversion. A conversion takes 11 ADC clocks, about 2.9 µs.
  unsigned int adc_read(unsigned char ch)
  {
      unsigned int r;
      AD0CR = (AD0CR & ~0xFFu) | (1u << ch); /* select channel (SEL field)     */
      AD0CR |= (1u << 24);                    /* START = 001: start conversion */
      do { r = AD0GDR; } while (!(r & 0x80000000u)); /* wait for DONE flag     */
      AD0CR &= ~(7u << 24);                   /* stop conversion               */
      return (r >> 6) & 0x3FF;                /* 10-bit RESULT (bits 15:6)     */
  }


4.4 UART Initialization
UART0 is configured for 9600 baud, 8 data bits, no parity and 1 stop bit (Table 7). PINSEL0 bits
3:0 are set to 0101 so that P0.0 is TXD0 and P0.1 is RXD0. With DLAB = 1, the divisor PCLK /



                                                  9
(16 × 9600) = 97.7, rounded to 98, is written to U0DLL; the actual baud rate is 9566, an error of
0.35 %.
  void uart0_init(void)
  {
      PINSEL0 = (PINSEL0 & ~0x0Fu) | 0x05u;    /* P0.0 = TXD0, P0.1 = RXD0       */
      U0LCR = 0x83;                            /* 8N1, DLAB = 1                  */
      U0DLL = ((PCLK_HZ / 16) + (BAUD / 2)) / BAUD;   /* divisor = 98            */
      U0DLM = 0;
      U0LCR = 0x03;                            /* DLAB = 0                       */
      U0FCR = 0x07;                            /* enable and reset FIFOs         */
  }

4.5 UART Transmission
uart0_putc() waits until the transmit holding register is empty (THRE = 1 in U0LSR) and then
writes the character to U0THR. uart0_puts() sends a complete string by calling uart0_putc() for
every character.
  void uart0_putc(char c)
  {
      while (!(U0LSR & 0x20));                  /* wait until THR is empty       */
      U0THR = c;
  }
  void uart0_puts(const char *s)
  {
      while (*s)
          uart0_putc(*s++);
  }


4.6 Timer0 Initialization
Timer0 counts PCLK cycles in hardware. T0PR = 14999 makes the timer counter increment
every 1 ms, and T0MR0 = 999 produces a match after 1000 ticks, which is 1 s. T0MCR = 0x03
generates an interrupt and resets the counter at every match. Timer0 is source 4 of the VIC and is
assigned to vectored slot 0 (Table 8).
  void timer0_init(void)
  {
      T0TCR = 0x02;                            /* reset counter                  */
      T0PR = (PCLK_HZ / 1000) - 1;             /* 14999 -> 1 ms per tick         */
      T0MR0 = SAMPLE_MS - 1;                   /* 999 -> match every 1 s         */
      T0MCR = 0x03;                            /* interrupt + reset on MR0       */
      VICVectAddr0 = (unsigned long)timer0_isr;
      VICVectCntl0 = 0x20 | 4;                 /* slot 0 enabled, Timer0 = 4     */
      VICIntEnable = (1u << 4);
      T0TCR = 0x01;                            /* start Timer0                   */
  }

4.7 Timer0 Interrupt
The interrupt service routine is kept very short: it sets sample_flag, clears the MR0 interrupt flag
by writing 1 to T0IR, and writes 0 to VICVectAddr to signal the end of the interrupt. The
keyword
  irq makes the ARM compiler generate the interrupt entry and exit code. The time-consuming
work is done in the main loop, not inside the interrupt.
       irq void timer0_isr(void)
   {
         sample_flag = 1;                           /* 1 s has elapsed                     */
         T0IR = 0x01;                               /* clear MR0 interrupt flag            */
         VICVectAddr = 0;                           /* end of interrupt                    */
   }


4.8 Data Processing
log_sample() reads the three channels in turn and converts the counts with integer arithmetic
only: a1 × 3300 / 1023 gives millivolts, which for the LM35 (10 mV per °C) equals tenths of a
degree Celsius; the LDR and soil-moisture counts are scaled to a percentage of full scale. The
values are formatted with sprintf() and sent through UART0. The activity LED on P0.7 is on
while the sample is being acquired and sent.
   void log_sample(void)
   {
       char buf[40];
       unsigned int a1, a2, a3, t10, light, moist;
       IO0SET = LED_PIN;                        /* activity LED on               */
       a1 = adc_read(1);                        /* LM35          (AD0.1)         */
       a2 = adc_read(2);                        /* LDR           (AD0.2)         */
       a3 = adc_read(3);                        /* soil moisture (AD0.3)         */
       t10   = (a1 * 3300u) / 1023u;            /* mV = tenths of deg C (10 mV/C) */
       light = (a2 * 100u) / 1023u;             /* percent of full scale         */
       moist = (a3 * 100u) / 1023u;             /* percent of full scale         */
       sample_no++;
       sprintf(buf, "Sample No     : %03u\r\n", sample_no);
       uart0_puts(buf);
       sprintf(buf, "Temperature   : %u.%u C\r\n", t10 / 10, t10 % 10);
       uart0_puts(buf);
       sprintf(buf, "Light         : %u %%\r\n", light);
       uart0_puts(buf);
       sprintf(buf, "Soil Moisture : %u %%\r\n", moist);
       uart0_puts(buf);
       uart0_puts("                                \r\n");
       uart0_puts("Data Logged Successfully\r\n\r\n");
       IO0CLR = LED_PIN;                        /* activity LED off              */
   }


4.9 Complete Program
The complete program initialises the PLL, GPIO, ADC, UART0 and Timer0 in that order, sends
the start-up banner and then enters an endless loop. The loop checks the volatile flag
sample_flag, which Timer0 sets every second; when it is set, the flag is cleared and log_sample()
reads the three sensors and transmits the results.

   #include <LPC214x.h>
   #include <stdio.h>
   #define PCLK_HZ    15000000UL      /* PCLK = CCLK / 4 = 15 MHz                     */
   #define BAUD       9600UL

#define LED_PIN      (1u << 7)       /* P0.7: optional activity LED            */
volatile unsigned char sample_flag = 0;     /* set by the Timer0 interrupt      */
unsigned int sample_no = 0;
/*                               clock                                      */
void pll_init(void)
{
     unsigned int t = 100000;                  /* lock time-out counter          */
     PLL0CFG = 0x24;                           /* M = 5, P = 2 -> CCLK = 60 MHz */
     PLL0CON = 0x01;                           /* enable PLL                      */
     PLL0FEED = 0xAA; PLL0FEED = 0x55;
     while (!(PLL0STAT & (1u << 10)) && --t); /* wait for PLL lock (time-out) */
     PLL0CON = 0x03;                           /* enable and connect PLL          */
     PLL0FEED = 0xAA; PLL0FEED = 0x55;
     MAMTIM = 0x03;                            /* flash accelerator timing        */
     MAMCR = 0x02;                             /* fully enabled                   */
     VPBDIV = 0x00;                            /* PCLK = CCLK / 4 = 15 MHz        */
}
/*                               GPIO                                       */
void gpio_init(void)
{
     IO0DIR |= LED_PIN;                        /* P0.7 as output                  */
     IO0CLR = LED_PIN;                         /* LED off                         */
}
/*                               ADC                                        */
void adc_init(void)
{
     PINSEL1 &= ~((3u << 24) | (3u << 26) | (3u << 28));
     PINSEL1 |= ((1u << 24) | (1u << 26) | (1u << 28)); /* AD0.1, AD0.2, AD0.3 */
     AD0CR = (1u << 21) | (3u << 8);           /* PDN = 1, CLKDIV = 3 (3.75 MHz) */
}
unsigned int adc_read(unsigned char ch)
{
     unsigned int r;
     AD0CR = (AD0CR & ~0xFFu) | (1u << ch); /* select channel (SEL field)        */
     AD0CR |= (1u << 24);                      /* START = 001: start conversion */
     do { r = AD0GDR; } while (!(r & 0x80000000u)); /* wait for DONE flag         */
     AD0CR &= ~(7u << 24);                     /* stop conversion                 */
     return (r >> 6) & 0x3FF;                  /* 10-bit RESULT (bits 15:6)      */
}
/*                               UART0                                      */
void uart0_init(void)
{
     PINSEL0 = (PINSEL0 & ~0x0Fu) | 0x05u;     /* P0.0 = TXD0, P0.1 = RXD0        */
     U0LCR = 0x83;                             /* 8N1, DLAB = 1                   */
     U0DLL = ((PCLK_HZ / 16) + (BAUD / 2)) / BAUD;    /* divisor = 98             */
     U0DLM = 0;
     U0LCR = 0x03;                             /* DLAB = 0                        */
     U0FCR = 0x07;                             /* enable and reset FIFOs          */
}
void uart0_putc(char c)
{
     while (!(U0LSR & 0x20));                  /* wait until THR is empty         */
     U0THR = c;
}
void uart0_puts(const char *s)
{
     while (*s)
         uart0_putc(*s++);
}
/*                               Timer0                                     */
   irq void timer0_isr(void)
{
     sample_flag = 1;                          /* 1 s has elapsed                 */
     T0IR = 0x01;                              /* clear MR0 interrupt flag        */
     VICVectAddr = 0;                          /* end of interrupt                */
}
void timer0_init(void)
{
     T0TCR = 0x02;                             /* reset counter                   */
     T0PR = (PCLK_HZ / 1000) - 1;              /* 14999 -> 1 ms per tick          */
     T0MR0 = SAMPLE_MS - 1;                    /* 999 -> match every 1 s         */
     T0MCR = 0x03;                             /* interrupt + reset on MR0        */
     VICVectAddr0 = (unsigned long)timer0_isr;
     VICVectCntl0 = 0x20 | 4;                  /* slot 0 enabled, Timer0 = 4      */
     VICIntEnable = (1u << 4);
     T0TCR = 0x01;                             /* start Timer0                    */
}
/* ------------------- acquisition, processing, output--------------------*/
void log_sample(void)
{
     char buf[40];

                                              13
      unsigned int a1, a2, a3, t10, light, moist;
      IO0SET = LED_PIN;                        /* activity LED on               */
      a1 = adc_read(1);                        /* LM35          (AD0.1)         */
      a2 = adc_read(2);                        /* LDR           (AD0.2)         */
      a3 = adc_read(3);                        /* soil moisture (AD0.3)         */
      t10   = (a1 * 3300u) / 1023u;            /* mV = tenths of deg C (10 mV/C) */
      light = (a2 * 100u) / 1023u;             /* percent of full scale         */
      moist = (a3 * 100u) / 1023u;             /* percent of full scale         */
      sample_no++;
      sprintf(buf, "Sample No     : %03u\r\n", sample_no);
      uart0_puts(buf);
      sprintf(buf, "Temperature   : %u.%u C\r\n", t10 / 10, t10 % 10);
      uart0_puts(buf);
      sprintf(buf, "Light         : %u %%\r\n", light);
      uart0_puts(buf);
      sprintf(buf, "Soil Moisture : %u %%\r\n", moist);
      uart0_puts(buf);
      uart0_puts("                                \r\n");
      uart0_puts("Data Logged Successfully\r\n\r\n");
      IO0CLR = LED_PIN;                        /* activity LED off              */
  }
  /*                               main                                       */
  int main(void)
  {
      pll_init();
      gpio_init();
      adc_init();
      uart0_init();
      timer0_init();
      uart0_puts("================================\r\n");
      uart0_puts("REMOTE DATA LOGGER\r\n");
      uart0_puts("================================\r\n");
      while (1)
      {
          if (sample_flag)                      /* set every second by Timer0      */
          {
              sample_flag = 0;
              log_sample();
          }
      }
  }

                                    7. CONCLUSION
A remote data logger was designed and implemented around the LPC2148 microcontroller. The
system acquires three analog parameters (temperature, light level and soil moisture) from an
LM35, an LDR and a soil-moisture sensor through the on-chip 10-bit ADC, converts the raw
counts into engineering units, and sends the results to a PC through UART0 at 9600 baud, 8N1,
once every second.
The ADC is essential because every sensor produces an analog voltage that the processor cannot
use directly; its channels AD0.1 to AD0.3 allow several sensors to share one converter. The
UART0 gives a simple, reliable link to the PC, with only the TXD0 line and a level converter
needed to display and store the readings. Timer0 makes the sampling periodic and independent
of the program flow, so that the interval stays accurate and the CPU is free between samples.
The integration of the three modules makes the software short, deterministic and easy to extend.
The program was developed in Embedded C using Keil µVision: the LPC2148 project was
created, main.c was added, the target was configured for a 12 MHz crystal, the project was built
successfully and the HEX file was generated. In the simulation the virtual terminal displayed the
sensor data at regular one-second intervals, verifying the periodic remote data logging.
Such a logger can be applied to greenhouse and agricultural monitoring, cold-storage and
industrial temperature recording, weather stations and laboratory experiments. Possible future
improvements are:
    replacing the wired link by a wireless one (ZigBee, GSM/GPRS or Wi-Fi);
    adding a time stamp from the on-chip real-time clock and storing the samples on an SD card;
    averaging several ADC samples, calibrating the sensors and adding alarm thresholds;
    using the remaining ADC channels for more sensors; and
    using the low-power modes of the LPC2148 between samples for battery-powered
      operation.
